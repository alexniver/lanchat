# 0.1.3 范围与验收标准

> 状态：已实现，验收中
> 目标：只读帮助页面，不是命令面板、不是交互式教程
> 关联：[README.md](README.md) · [02-ui.md](02-ui.md) · [03-content.md](03-content.md)

## 1. 背景

0.1.2 已经支持聊天、文件传递、成员侧边栏和较多快捷键。新用户需要一份不离开 TUI 就能查看的说明：

- 不必退出程序去读 README；
- 不必记住所有键位；
- 可用 `j/k` 浏览较长内容；
- 看完按 `Esc` 立即回到聊天。

## 2. 目标

- 在 List 层按 `?` 打开帮助。
- 帮助内容显示在上方主面板，底部保留 3 行状态栏。
- `j` / `k` 上下滚动；`Esc` 退出。
- 状态栏明确显示“按 Esc 退出帮助”和滚动位置。
- 帮助内容覆盖常用操作，并尽量反映当前 keymap。
- 不改变 List 选中、消息历史、网络连接和文件传递状态。

## 3. 非目标（0.1.3 不做）

| 不做 | 说明 |
| --- | --- |
| 交互式教程 | 不引导用户逐步操作 |
| 帮助内执行命令 | 只读文本，不发送、不 `/send` |
| 搜索/跳转/链接 | 不做；只有 j/k 滚动 |
| 鼠标/滚轮 | 不做 |
| 从 Compose/Members 打开 | 0.1.3 只从 List 进入 |
| 修改 keymap 的 UI | 帮助只显示，不编辑 |
| 历史/收藏/FAQ 管理 | 静态内容 |
| 网络/文件状态面板 | 帮助不是 dashboard；状态栏可带在线数 |
| 帮助内容持久化 | 每次打开从顶部开始（或有记忆，见 OQ） |

| --- | --- | --- |
| US-01 | 我在消息列表按 `?`，看到帮助页面 | P0 |
| US-02 | 帮助内容超过一屏时，我按 `j/k` 上下查看 | P0 |
| US-03 | 状态栏告诉我按 `Esc` 可以退出 | P0 |

## 5. 功能需求

### FR-01 打开帮助

- `[必须]` 在 List 层按 `?` 打开帮助。
- `[必须]` 打开后帮助 Layer 位于栈顶，List 仍在栈底。
- `[必须]` 帮助打开时不显示 List 的选中高亮、Compose、成员侧边栏。
- `[必须]` Compose 下按 `?` 只输入字符 `?`，不打开帮助。
- `[应该]` Members 层按 `?` 不打开帮助（或忽略，见 OQ-13-03）。
- `[必须]` `?` 作为 List action 可配置；默认绑定 `?`（见 OQ-13-01）。

### FR-02 帮助布局

- `[必须]` 上方帮助 panel 占据主区域；下方状态栏保留 3 行。
- `[必须]` 帮助 panel 有边框和标题（建议 ` 帮助 `）。
- `[必须]` 帮助 panel 宽度用满终端；不显示右侧成员栏。
- `[必须]` 帮助内容在 panel 内自动换行，中文按显示宽度折行。
- `[必须]` 终端小于最小尺寸（60×15）时显示“终端太小”提示，不崩溃。
- `[应该]` 帮助状态栏与 List 状态栏样式一致，但内容替换为帮助提示。

### FR-03 帮助内容

- `[必须]` 至少覆盖：
  - 快速开始（`i`、`/`、`?`、`Esc`、`Q`）；
  - 消息列表与自动/手动选中；
  - 输入 panel（`i`，Enter/Esc，文本编辑键）；
  - 文件传递（`/send file`、`/recv file`、保存目录、超时/重名）；
  - 成员侧边栏（`Space u`）；
  - 网络/状态（在线 N、连接状态、`Space r`/`Space d`）；
  - 配置/历史/日志路径；
  - 已知限制/安全提醒。
- `[应该]` 键位提示来自当前 `Keymap`，用户重映射后帮助同步变化。
- `[应该]` 显示当前版本（`env!("CARGO_PKG_VERSION")`）。
- `[必须]` 帮助内容是只读纯文本，不触发任何效果。
- `[应该]` 内容分节带标题，方便滚动定位。

### FR-04 滚动

- `[必须]` `j` 向下滚动一行，`k` 向上滚动一行。
- `[必须]` 滚动位置钳制在 `0..=max_offset`，不能越界。
- `[必须]` 内容不足一屏时 `max_offset = 0`，j/k 无视觉变化。
- `[必须]` 状态栏显示当前位置（行号或百分比）。
- `[应该]` 支持 `Home`/`End`（顶部/底部）和 `PgUp`/`PgDn`（可选，P1）。
- `[必须]` 滚动不改变 List 的 selected/follow_latest。
- `[应该]` 打开帮助时从顶部开始（或恢复上次位置，OQ-13-06）。

### FR-05 退出

- `[必须]` `Esc` 退出帮助，弹出帮助 Layer，回到 List。
- `[必须]` 退出后 List 的选中位置、自动/手动模式、未读提示保持进入前状态。
- `[必须]` 退出后消息列表滚动位置不因帮助而改变。
- `[应该]` 帮助内 `Q` 不退出整个程序（见 OQ-13-02）。
- `[必须]` 帮助内不响应 `i`、`/`、`y`、`Y`、`Space u` 等 List action。
- `[应该]` `Ctrl+C` 不退出，只清除状态或忽略。

### FR-06 状态栏

- `[必须]` 至少显示：`按 Esc 退出帮助`。
- `[必须]` 显示滚动位置，例如 `帮助 12/80` 或 `滚动 15%`。
- `[应该]` 显示 `j/k 滚动` 提示。
- `[应该]` 显示当前版本和在线人数，例如 `LanChat 0.1.3 · 在线 2`。
- `[必须]` 状态栏不覆盖帮助内容；固定 3 行。
- `[必须]` 帮助状态栏的临时错误/提示不依赖 List status。

### FR-07 边界/副作用

- `[必须]` 打开/关闭帮助不发送网络消息、不写历史、不触发文件操作。
- `[必须]` 帮助不影响后台网络事件；关闭后 List 继续显示。
- `[必须]` 帮助打开时收到的消息仍进入 List；退出后可见，且不改变自动/手动语义。
- `[必须]` 帮助没有“已读/未读”语义，不增加 unread。
- `[应该]` 帮助打开时状态栏的在线数/连接状态仍可更新（不要求）。

## 6. 非功能需求

| ID | 需求 | 目标 |
| --- | --- | --- |
| NFR-01 | 打开延迟 | 按键后立即显示，无网络/磁盘等待 |
| NFR-02 | 滚动 | 单行滚动，边界稳定，无越界 panic |
| NFR-03 | 中文 | 按显示宽度换行/截断，不出现乱码 |
| NFR-04 | 小终端 | 60×15 以下显示提示，不崩溃 |
| NFR-05 | 回归 | 0.1.2 全部测试继续通过 |
| NFR-06 | 只读 | 不产生 Effect/网络/历史副作用 |
| NFR-07 | 键位 | 默认键位和自定义 keymap 下都能进入/退出 |
| NFR-08 | 内容 | 帮助内容与当前版本/功能一致 |

## 7. 验收标准

### 7.1 打开/退出

- [ ] List 按 `?` 出现帮助 panel 和帮助状态栏。
- [ ] 帮助 panel 不显示消息列表选中高亮、不显示成员栏。
- [ ] `Esc` 退出帮助，回到 List。
- [ ] 退出后 List 选中项与进入前一致（自动/手动都不变）。
- [ ] Compose 下 `?` 输入字符，不打开帮助。
- [ ] Members 下 `?` 不会打开帮助（按最终决定）。

### 7.2 滚动

- [ ] 内容超过一屏时 `j` 下移一行、`k` 上移一行。
- [ ] 到顶部/底部后继续按不越界。
- [ ] 内容不足一屏时 j/k 无异常。
- [ ] 状态栏显示当前位置。
- [ ] `Esc` 不依赖滚动位置。

### 7.3 内容/键位

- [ ] 帮助包含快速开始、消息、文件传递、成员、配置、限制。
- [ ] 帮助包含当前版本号。
- [ ] 修改 keymap 后，帮助中的键位提示反映新配置（若实现动态提示）。
- [ ] 中文/长行换行正确。

### 7.4 边界/回归

- [ ] 帮助打开时收到消息，退出后消息仍在且选中规则正确。
- [ ] 打开/关闭帮助不写历史、不发网络消息。
- [ ] 终端 resize 后不 panic，滚动位置钳制。
- [ ] 0.1.2 全部测试通过。

## 8. 假设

- 帮助内容是编译进二进制的静态文本，不需要外部文件。
- 帮助内容使用中文；终端支持 UTF-8。
- 状态栏 3 行高度不变。
- 帮助是顶层 Layer，和 Compose/Members 一样压栈。
- 0.1.3 不做帮助内搜索/链接/命令执行。
