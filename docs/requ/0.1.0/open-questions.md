## P0：不确认就无法开始实现

### OQ-25 Compose 下 Enter 的精确语义

**背景**：需求同时出现“输入文本回车，信息显示在列表”和“在显示输入框 panel 的状态下，按 esc/enter，输入框 panel 消失，无信息上列表”。需要明确空/非空、Enter/Esc 的分工。

**选项**：

| 选项 | 行为 | 说明 |
| --- | --- | --- |
| A（推荐） | Enter 非空/非纯空白：发送并 pop；Enter 空/纯空白：pop 不发送；Esc：pop 不发送 | 符合“输入文本后回车发送”，也解释“空 Enter 关闭” |
| B | Enter 永远只关闭、不发送；发送用另一个键 | 与“回车发送”矛盾，不推荐 |
| C | Enter 永远发送（空消息也发）；Esc 取消 | 会产生空消息，不推荐 |

**推荐**：A。`trim()` 后为空视为空；发送前清空输入；Esc 丢弃草稿。

**状态**：**已确认**（D-015）；实现按 A。

### OQ-26 退出键

**背景**：0.1.0 没有命令模式时，需要一个安全退出键；`Esc`/`Enter` 已用于 pop。

**选项**：

| 选项 | 说明 |
| --- | --- |
| A（推荐） | `Q`（List 层）退出；Compose 下不响应，先 Esc 回 List |
| B | `q`（List 层）退出；简单但容易误触 |
| C | `:q` 命令；需要额外命令层，0.1.0 核心变复杂 |
| D | `Ctrl+C` 退出；与“取消/复制”习惯冲突，不推荐 |

**推荐**：A。状态栏显示 `Q 退出`；退出前 flush 历史、恢复终端。保留键，不允许 keymap 解绑。

**状态**：**已确认**（D-013）；采用 A。

### OQ-16 保留键范围

**背景**：键位可自定义后，用户可能把输入提交/取消键改坏。

**推荐**：

- Compose `Enter`：发送/取消，不可改；

- List `Q`：退出，不可改（已确认）；
- List `i`：打开输入，默认可用；允许用户改，但如果全部改掉可用 `--no-config` 恢复。

**状态**：待确认

### OQ-17 键位配置格式与加载方式

**背景**：0.1.0 核心交互没有命令模式，`:keymap reload` 可能没有入口。

**推荐**：

- 文件：`~/.config/lanchat/keymap.toml`。
- 只配置 `[list]`；Compose 的 Enter/Esc 保留。
- 键优先：`"j" = "cursor_down"`；`"none"` 解绑；多键序列可选。
- 启动时加载；坏 TOML/未知 action 回退默认并警告。
- `--no-config` 跳过用户配置。
- 热重载 `:keymap reload` 列为 P2（需要命令层）；0.1.0 可要求重启生效。

**待确认**：

1. 是否接受“改 keymap 后重启生效”（推荐 0.1.0 接受）。
2. 坏配置：回退默认（推荐）还是拒绝启动。
3. 是否允许自定义 `Q`（建议不允许，保留退出）。

**状态**：待确认

### OQ-27 `datetime` 显示格式

**背景**：消息格式固定为 `[name][datetime]: message`，但 datetime 具体格式未定。

**选项**：

| 选项 | 示例 | 说明 |
| --- | --- | --- |
| A（推荐） | `2026-11-19 10:30:05` | 完整日期时间；信息量大，占宽 |
| B | `11-19 10:30` | 更短；跨年不清晰 |
| C | `10:30:05` | 最简；跨天不清晰 |

**推荐**：A。存储用 RFC3339；显示用本地时间 `YYYY-MM-DD HH:MM:SS`。若 80 列太挤，0.2 可配置短格式。

**状态**：**已确认**（D-016）；采用 A。

### OQ-29 剪贴板方案

**背景**：`y/Y` 要复制到系统剪贴板；终端/SSH/headless 环境差异大。

**选项**：

| 选项 | 说明 |
| --- | --- |
| A（推荐） | 本机 `arboard`（X11/Wayland/macOS/Windows）；失败/远程尝试 OSC 52 |
| B | 只用 OSC 52 | 无平台依赖；但很多终端不启用/不支持 |

**推荐**：A。成功统一提示“复制成功”；都失败提示“复制失败”。复制在后台线程，不阻塞 UI。

### OQ-31 手动模式下自己发送消息，是否自动跳最新？

**背景**：默认自动模式会选最新；手动模式用于浏览历史。发送消息也是“新消息”，需要明确是否例外。

**选项**：

| 选项 | 行为 | 说明 |
| --- | --- | --- |
| A（推荐） | 不跳：保持手动模式和原选中；按 `j` 到最新后恢复自动 | 严格按“手动模式不自动选最新”的描述；0.1.0 本地可验证 |
| B | 跳：发送后选新消息并回到自动模式 | 更常见的聊天 UX，但会打断浏览 |

**推荐**：A。这样 0.1.0 在没有网络/外部消息时也能验证手动模式；如果希望发送后跳最新，改 B。

**状态**：待确认

## 已确认但需要落实到文档的细节

1. `Esc`/`Enter` 只 pop 栈；基础 List 不 pop。
2. Compose 下 `j/k/y/Y/i` 是文字输入，不是列表动作。
3. 新消息自动选最新；默认选最后。
4. 复制成功状态显示 2 秒。
5. 中文宽度用 `unicode-width`；不加载字体。
6. 终端异常/panic 必须恢复 raw mode 和 alternate screen。
7. 日志不记录聊天正文；历史文件权限 `0600`。
8. 0.1.0 不引入网络/文件共享依赖；`05-network.md` 仅 0.2 参考。
9. 坏 keymap 不能把用户锁死；`--no-config` 兜底。
