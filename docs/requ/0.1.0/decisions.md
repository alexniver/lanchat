## D-001 从零重写，而不是增量修补

- **状态**：已确认（来自 2026-11-19 用户请求）
- **背景**：旧版功能不全、bug 较多，TUI、状态、网络、文件共享耦合在一起。
- **决策**：0.1.0 从零重写；旧实现只作参考，不直接复用。
- **影响**：根项目先以占位入口保证可编译；实现阶段重新设计模块边界。

## D-002 旧代码移入 `old/`，不参与编译

- **状态**：已确认
- **决策**：旧 `src/`、`SPEC.md`、`README.md`、`Cargo.toml`、`Cargo.lock`、`log/` 移入 `old/`；根 `Cargo.toml` 使用 `[workspace] exclude = ["old"]`。
- **影响**：`cargo check` 只检查新实现；需要参考旧实现时进入 `old/` 阅读或单独构建。

## D-003 0.1.0 只做聊天，删除文件共享

- **状态**：已确认
- **决策**：文件共享、文件列表、下载、SHA256、base64 文件传输全部不进入 0.1.0。
- **影响**：移除 `sha2`、文件传输协议、共享目录等设计；依赖按需重新引入。

## D-004 键位采用 Helix-inspired 风格

- **状态**：已确认；后续由 D-010 补充为“可自定义”
- **决策**：UI 用栈式 Layer；默认键位借用 Helix 的概念，但 0.1.0 核心只保留 List `i/j/k/y/Y/Q` 与 Compose `Enter/Esc`；`gg/G`、搜索、命令等为 P2 可选。
- **影响**：需要一个可测试的键位/层栈解析器，而不是 `match key.code` 散落各处；List 键位必须可被用户配置覆盖。

## D-005 先讨论需求，再冻结实现

- **状态**：已确认
- **决策**：0.1.0 范围、键位表、联网范围、历史策略等先在 `docs/requ/0.1.0/` 达成一致，再进入实现。
- **影响**：当前不实现聊天功能；根项目只保留占位入口和文档。

## D-006 0.1.0 只做单机，联网推迟到 0.1.1

- **状态**：已确认（2026-11-19）
- **决策**：0.1.0 不实现局域网发现、TCP 连接、节点/成员、重连、心跳；这些整体移到 0.1.1。
- **影响**：
  - 0.1.0 的“聊天”是单进程本地聊天：双 panel、输入栈、选中/复制、本地历史、可配置键位。
  - `05-network.md` 保留为 0.1.1 预留设计，不进入 0.1.0 验收。
  - 0.1.0 不引入 `mdns-sd`、网络协议、socket 相关依赖。

## D-007 0.1.0 使用单房间 `#lobby`

- **状态**：已确认
- **决策**：所有消息属于本地房间 `#lobby`；UI 显示 `#lobby`，协议值（0.1.1）使用 `lobby`。

## D-008 本地历史使用 JSONL 持久化

- **状态**：已确认
- **决策**：聊天消息追加写入本地 JSONL；启动加载最近 N 条；文件权限 `0600`；不做多端同步。
- **影响**：新增 `storage/history` 模块；历史损坏时跳过坏行；`:clear` 只清视图，不删历史。

## D-009 Compose 层 Enter 发送，0.1.0 单行输入

- **状态**：已确认
- **决策**：Enter 发送；0.1.0 不做多行输入；空消息不发送；超长拒绝；发送后 pop Compose（选中规则见 D-014）。
- **影响**：输入组件做水平滚动；`Alt+Enter`/多行放到 0.1.1；Enter/Esc 精确语义见 D-015。

## D-010 键位可自定义，默认 Helix-inspired

- **状态**：已确认（对应 OQ-05 选项 C）
- **决策**：
  - 0.1.0 必须支持用户自定义键位，不是“固定 Helix 键位”。
  - 内置一套 Helix-inspired 默认键位，0.1.0 核心为 List `i/j/k/y/Y/Q`、Compose `Enter/Esc`；`gg/G`、搜索、命令等属于 P2 可选。
  - 键位配置文件独立（建议 `~/.config/lanchat/keymap.toml`）；0.1.0 启动时加载，改键后重启生效；热重载列为 P2。
  - 核心保留键保留不可重映射：List 的 `Q`、Compose 的 `Enter`/`Esc`；保证用户不会把自己锁死。
  - `--no-config` / 配置文件损坏时回退默认键位。
- **影响**：
  - 键位引擎必须数据驱动，动作注册表稳定、可校验；不能把 `match key.code` 写死在 TUI 里。
  - 0.1.0 范围增加：keymap 配置解析、合并、冲突检测、`--no-config`；`:keymap` 命令列为 P2。
  - 原 OQ-13 的“0.1.1 再做自定义键位”作废，提前到 0.1.0。

## D-011 0.1.0 核心交互按 08 文档实现

- **状态**：已确认（来自 2026-11-19 详细补充）
- **决策**：
  - 上下双 panel：上信息列表，下状态。
  - 消息格式 `[name][datetime]: message`。
  - `i` 在信息列表下方弹出输入 panel；Enter 非空发送、空/纯空白取消、Esc 取消。
  - UI 状态用 `Vec<Layer>` 栈；`Esc`/`Enter` pop；基础 List 不 pop。
  - List 默认选最后；新消息自动选最新；`j/k` 移动；`y` 复制正文、`Y` 复制完整行；状态“复制成功”。
  - Compose 下选中高亮消失，除 Enter/Esc 外不响应应用快捷键（字符仍输入）。
- **影响**：
  - 键位分发必须按栈顶；Compose 下不能走 List 键位树。
  - 0.1.0 核心验收以 [08-core-interaction.md](08-core-interaction.md) 为准。
  - 搜索/命令/帮助降为 P2 可选，不阻塞核心验收。

## D-012 0.1.0 不加载字体，中文由终端字体保证

- **状态**：已确认（技术事实 + 用户要求支持中文）
- **决策**：TUI 程序不加载字体；终端使用 CJK 等宽字体；程序用 `unicode-width` 计算显示宽度。
- **影响**：README/帮助需说明推荐字体；中文对齐问题优先归因于终端字体；不引入字体渲染依赖。


## D-013 List 层 `Q` 退出

- **状态**：已确认（2026-11-19）
- **决策**：在信息 panel（List 层）按大写 `Q` 退出；Compose 下 `Q` 是普通字符（先 Esc 回 List 再 Q）。
- **影响**：`Q` 是保留键，不允许 keymap 解绑；状态栏提示 `Q 退出`；Compose 下不响应非 Enter/Esc 的应用快捷键。

## D-014 选中分自动/手动两种模式

- **状态**：已确认（2026-11-19）
- **决策**：
  - 默认自动模式：选中最后一条；新消息（含自己发送）自动选中最新并滚动到底。
  - 用户 `j/k` 选中非最新消息 → 手动模式：新消息不改变选中/滚动。
  - 用户 `j/k` 选回最新消息 → 自动模式恢复。
  - 状态 panel 显示 `自动`/`手动`。
  - 手动模式下自己发送消息：不自动跳最新，保持原选中；按 `j` 到最新后恢复自动（按当前理解，OQ-31 待确认）。
- **影响**：`ListState` 增加 `follow_latest: bool`；新消息处理、Compose 发送后选中、状态展示、测试用例都要覆盖两种模式。


## D-015 Compose Enter 语义

- **状态**：已确认（2026-11-19）
- **决策**：Compose 下 `Enter` 在输入非空（trim 后）时发送并 pop；输入为空/纯空白时 pop 但不产生消息；`Esc` 始终 pop 且不产生消息。
- **影响**：输入框在 Enter 前做 trim 校验；空白消息不进入列表/历史；Esc 丢弃草稿。

## D-016 datetime 显示格式

- **状态**：已确认（2026-11-19）
- **决策**：消息格式中的 datetime 使用本地时间 `YYYY-MM-DD HH:MM:SS`，例如 `[alice@arch][2026-11-19 10:30:05]: 你好`。
- **影响**：存储用 RFC3339；显示时格式化；80 列下可能较长，0.1.1 可加短格式配置。
