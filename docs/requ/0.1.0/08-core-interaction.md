## 1. 启动后的界面

界面分上下两个常驻 panel：

```text
┌ 信息列表 ──────────────────────────────────────────────────────┐
│ [alice@arch][2026-11-19 10:30:01]: 你好                         │
│ [alice@arch][2026-11-19 10:30:05]: 在                           │
│ [alice@arch][2026-11-19 10:31:12]: 今天先到这里                 │
│                                                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
┌ 状态 ──────────────────────────────────────────────────────────┐
│ 在线 1（本机） · 消息 3 · 选中 3/3 · 自动              │
└─────────────────────────────────────────────────────────────────┘
```

- **上 panel**：信息列表，占剩余高度。
- **下 panel**：状态信息，固定高度。
- 0.1.0 不联网；“在线 1（本机）”只是本机节点，不伪造其他 peer。
- 信息格式严格为：`[name][datetime]: message`。
- 启动时默认选中最后一条；没有消息时不选中。

### 1.1 状态 panel 高度

**建议 3 行**：

- 第 1 行：上边框；
- 第 2 行：状态文本（1 行）；
- 第 3 行：下边框。

终端里没有“字体大小”概念，一个终端单元格就是一行文字的高度。3 行 = 一行文本 + 上下边框，比一行文字略高，符合“比字体大小大些”的要求，也不会挤压信息列表。若不用边框，可以退化为 2 行（1 行文本 + 1 行分隔线），但 0.1.0 推荐 3 行带边框。

### 1.2 中文字体

**TUI 程序不加载字体。** 终端里的字体由终端模拟器（Alacritty、Kitty、WezTerm、Windows Terminal、iTerm2 等）提供；程序只输出 UTF-8 字符和 ANSI 序列。

要正确显示中文：

1. 终端使用**支持 CJK 的等宽字体**，例如 Sarasa Mono SC、Noto Sans Mono CJK SC、Maple Mono NF CN、更纱黑体等；也可以用 JetBrains Mono 等西文字体 + CJK fallback。
2. 终端 locale/编码为 UTF-8（`LANG=*.UTF-8`）。
3. 程序用 `unicode-width` 计算显示宽度：中文/全角字符占 2 列，ASCII 占 1 列；不能用字节数或 `chars().count()` 定位光标/折行。
4. 输入法由终端/系统处理；程序接收的是提交后的字符。候选框位置/IME 行为取决于终端，0.1.0 不做自定义候选框。

> 结论：不需要在 Rust 里加载字体；需要用户在终端里配置 CJK 等宽字体。若字体缺字，会显示 tofu（□），这是终端字体问题，不是程序能修复的。

## 2. 状态 panel 内容

状态文本一行，字段用 ` · ` 分隔：

```text
在线 1（本机） · 消息 3 · 选中 3/3 · 自动
```

| 字段 | 说明 |
| --- | --- |
| `本地` | 0.1.0 固定；0.1.1 可换成连接状态 |
| `在线 N（本机）` | 0.1.0 固定 N=1；0.1.1 显示 peer 数 |
| `消息 N` | 当前信息列表的消息数 |
| `选中 i/N` | 当前选中的第 i 条（1-based）/总数；无消息时显示 `选中 -/-` |
| `自动` / `手动` | 选择模式；见 3.2 |
| 临时提示 | 复制成功时追加 ` · 复制成功`，2 秒后消失；失败显示 ` · 复制失败` |
| 输入模式 | 输入 panel 显示时，可显示 `输入中 · Enter 发送 · Esc 取消` |

状态 panel 始终存在，不随 stack 层变化而消失。

## 3. 信息列表

### 3.1 消息格式

每条消息渲染为一行逻辑文本：

```text
[name][datetime]: message
```

- `name`：本机昵称，默认 `username@hostname`；0.1.0 所有消息都是本机。
- `datetime`：本地时间，建议 `YYYY-MM-DD HH:MM:SS`（RFC3339 存储，显示时格式化）。
- `message`：用户输入正文；保留空格；不支持多行输入（0.1.0）。
- 长消息按终端宽度折行；逻辑上仍是一条消息，选中时整条高亮。
- 示例：

```text
[alice@arch][2026-11-19 10:30:01]: 你好
[alice@arch][2026-11-19 10:30:05]: 在
```

### 3.2 选中模式（自动 / 手动）

List 层有两种选择模式：

| 模式 | 进入 | 新消息到达 |
| --- | --- | --- |
| 自动 | 默认；用户选中的是最后一条 | 自动选中最新并滚动到底 |
| 手动 | 用户用 `j/k` 选中了非最新消息 | 不改变选中/滚动；消息数增加 |

- 启动默认自动，选中最后一条；没有消息时无选中。
- `j/k` 移动后：
  - 若新选中项是最后一条 → 自动模式；
  - 否则 → 手动模式。
- **手动模式下，新消息（包括自己发送的）不自动选中**；选中项保持，状态 panel 显示 `手动`。
- **自动模式下，新消息（包括自己发送的）自动选中最新并滚动到底**；状态显示 `自动`。
- 用户从手动模式用 `j` 一路移到最新 → 自动模式恢复。
- 选中项高亮（整条消息；折行时所有显示行一起高亮）。
- 选中项必须可见；移动时自动滚动；列表滚动按显示行，但 `j/k` 以“消息条”为单位。
- 没有消息时：不显示选中高亮；`j/k` 无动作；`y/Y` 提示“没有可复制的消息”（或忽略）。

### 3.3 复制

在 List 模式：

| 键 | 复制内容 | 示例 |
| --- | --- | --- |
| `y` | 仅正文 `message` | `你好` |
| `Y` | 完整格式 `[name][datetime]: message` | `[alice@arch][2026-11-19 10:30:01]: 你好` |

- 复制成功后状态 panel 显示 ` · 复制成功`，2 秒后消失。
- 复制失败显示 ` · 复制失败`（例如剪贴板不可用）。
- 复制到系统剪贴板；SSH/远程终端优先尝试 OSC 52，失败时提示。
- 建议实现：本地优先 `arboard`（X11/Wayland/Windows/macOS），失败再尝试 OSC 52；具体见 OQ-29。

## 4. 输入 panel 与 stack

### 4.1 布局

按 `i` 后，在信息列表 panel **下方**弹出输入 panel；状态 panel 仍在最底部：

```text
┌ 信息列表 ──────────────────────────────────────────────────────┐
│ [alice@arch][2026-11-19 10:30:01]: 你好                         │
│ [alice@arch][2026-11-19 10:30:05]: 在                           │
│                                                                 │
├ 输入 ──────────────────────────────────────────────────────────┤
│ > 你好▌                                                         │
└─────────────────────────────────────────────────────────────────┘
┌ 状态 ──────────────────────────────────────────────────────────┐
│ 输入中 · Enter 发送 · Esc 取消 · 消息 2                        │
└─────────────────────────────────────────────────────────────────┘
```

- 输入 panel 固定 3 行（上边框 + 1 行输入 + 下边框）。
- 输入 panel 出现时，信息列表高度减少；列表仍可见，但**选中高亮消失**。
- 输入 panel 消失后，信息列表恢复高度。

### 4.2 状态 stack

整个 UI 状态用 **stack 压 enum** 表示：

```rust
enum Layer {
    List,                 // 基础层：信息列表 + 状态
    Compose(ComposeState),// 输入层：信息列表 + 输入 panel + 状态
}

struct App {
    layers: Vec<Layer>,   // 至少有一个 List
    // ...
}
```

- 启动：`layers = [List]`。
- List 下按 `i`：`layers.push(Compose(...))`；显示输入 panel。
- Compose 下按 `Esc` 或 `Enter`：`layers.pop()`；输入 panel 消失。
- 基础 `List` 永不 pop；`Esc`/`Enter` 在 List 下不退出程序。
- 渲染时先画常驻的信息列表/状态，再根据栈顶决定是否画输入 panel。
- 键位分发只看栈顶：
  - 栈顶 `List`：走 List 键位（`i`、`j`、`k`、`y`、`Y`、退出等）。
  - 栈顶 `Compose`：只处理 `Enter`/`Esc` 两个应用快捷键；其余按键交给输入框文本编辑。
- 未来加 Help/Confirm 时继续压栈；`Esc` 统一 pop。

### 4.3 Compose 下的按键规则

**只响应 `Enter` 和 `Esc` 两个应用快捷键；其他快捷键一律不响应。**

- 普通字符（包括 `i`、`j`、`k`、`y`、`Y`）都作为文本输入，不触发列表动作。
- `Esc`：pop，丢弃输入，不产生消息。
- `Enter`：
  - 输入非空（trim 后）：生成消息，追加到列表，pop；自动模式选中新消息并滚动到底，手动模式保持原选中，状态显示消息数/已发送。
  - 输入为空/纯空白：pop，不产生消息。
- 方向键/Home/End/Backspace/Delete 等编辑键仍由输入框处理（它们不是应用快捷键）。
- `Q`、`q`、`Ctrl+C` 等：Compose 下不作为应用快捷键；`Q`/`q` 作为普通字符输入，避免误触退出。用户要取消用 `Esc`。
- 选中效果在 Compose 下隐藏；`j/k` 不会移动列表，而是输入字符 `j`/`k`。
- 输入 panel 关闭后：
  - 发送：自动模式选中新消息；手动模式保持 `saved_selected`；见 OQ-31；
  - 取消：恢复打开输入 panel 前的选中项（建议，见 OQ-28）。

### 4.4 输入框

- 单行文本；支持中文/emoji；水平滚动；光标可见。
- `Backspace`/`Delete` 按字符边界删除；`←/→` 按字符边界移动。
- `Enter` 发送；不支持多行。
- 粘贴：换行转空格；过滤控制字符。
- 空白消息不发送。
- 单条消息上限 16 KiB；超限提示，不发送。
- 输入 panel 消失时清空输入（取消即丢弃；发送后清空）。

## 5. 键位总表（0.1.0 核心）

| 模式/层 | 键 | 动作 | 说明 |
| --- | --- | --- | --- |
| List | `i` | push Compose | 打开输入 panel |
| List | `j` | 下移选中 | clamp |
| List | `k` | 上移选中 | clamp |
| List | `y` | 复制正文 | 状态“复制成功” |
| List | `Y` | 复制完整行 | `[name][datetime]: message` |
| List | `Esc` | 无动作/清除临时提示 | 不退出 |
| List | `Enter` | 无动作 | 不发送（发送在 Compose） |
| Compose | `Enter` | 发送（非空）/取消（空） | pop |
| Compose | `Esc` | 取消 | pop，丢弃输入 |
| Compose | 其他字符 | 文本输入 | 不触发列表动作 |
| List | `Q` | 退出 | 仅 List；Compose 下 `Q` 是普通字符；OQ-26 |
| List | `Ctrl+C` | 无动作/清除提示 | 不退出 |
| Compose | `Q`/`q` | 输入字符 | 不退出；先 Esc 回 List 再 Q |

> 退出键已确认：**List 层按 `Q` 退出**；Compose 下 `Q` 是普通字符，先 `Esc` 回 List 再按 `Q`。状态栏提示 `Q 退出`。
>
> 键位可自定义（D-010）仍保留：List 的 `i/j/k/y/Y/quit` 可通过 `keymap.toml` 改；`Compose` 的 `Enter/Esc` 是保留键，不可改。

## 6. 状态转移

```text
List / 自动（默认，选中最后一条）
  │ j/k 到非最新                  │ 新消息
  ▼                              ▼
List / 手动（选中保持）        List / 自动（选中最新）

List / 自动 ── j/k 到最新 ──► List / 自动
List / 手动 ── j/k 到最新 ──► List / 自动

List / 自动 ── i ──► Compose ── Enter 非空 ──► List / 自动（选中新消息）
List / 手动 ── i ──► Compose ── Enter 非空 ──► List / 手动（保持原选中）
Compose ── Esc / 空 Enter ──► 回到原来的 List 模式与选中
```

- 0.1.0 新消息只在 Compose 的 Enter 非空时产生；手动模式下发送不自动跳转。
- 0.1.0 没有网络/后台消息；不存在“Compose 中收到别人消息”的情况。
- 若未来有后台消息，自动/手动模式同样适用；0.1.0 不处理。

## 7. 中文与宽度细节

- 渲染/光标/折行使用显示列宽：CJK 2 列，ASCII 1 列，emoji 2 列（按 `unicode-width`）。
- 输入光标按字节边界安全移动，但水平滚动按显示宽度计算。
- 消息行 `[name][datetime]: message` 中的中文 body 折行时，续行不重复 header（建议），或整行续行；0.1.0 采用“整条消息折行，续行缩进/无 header”的方式，选中高亮覆盖所有续行。
- 状态 panel 的中文字段也按显示宽度截断，不能按字节截断。
- 若终端宽度不足以显示 header，优先截断/折行 body，不 panic。

## 8. 验收标准（本文范围）

- [ ] 启动后显示上下两个 panel；信息列表在上，状态在下方 3 行。
- [ ] 状态显示 `在线 1（本机） · 消息 N · 选中 i/N · 自动/手动`。
- [ ] 消息显示格式为 `[name][datetime]: message`。
- [ ] 默认自动模式，选中最后一条。
- [ ] 自动模式下新消息自动选中最新；手动模式下新消息不改变选中。
- [ ] `j/k` 移到非最新 → 手动；再移到最新 → 自动。
- [ ] `j/k` 上下移动选中；到顶/到底 clamp；选中项可见。
- [ ] `y` 复制正文；`Y` 复制完整格式；状态显示“复制成功”。
- [ ] `i` 在信息列表下方弹出输入 panel；选中高亮消失。
- [ ] Compose 下输入中文正常；`j/k/y/Y/i` 作为字符输入，不触发列表动作。
- [ ] Compose 下 `Esc` 关闭 panel，不产生消息。
- [ ] Compose 下空 `Enter` 关闭 panel，不产生消息。
- [ ] Compose 下非空 `Enter` 追加消息、关闭 panel；自动模式选中新消息，手动模式保持原选中。
- [ ] 手动模式下自己发送消息不自动跳；按 `j` 到最后一条后恢复自动。
- [ ] 状态 stack 为 `Vec<Layer>`；`Esc`/`Enter` pop；基础 List 不被 pop。
- [ ] 终端使用 CJK 等宽字体时中文对齐正常；无 tofu/错位（字体本身缺字除外）。
- [ ] List 下 `Q` 退出；Compose 下 `Q` 输入字符；Esc 回 List 后 `Q` 可退出。
- [ ] 0.1.0 没有任何网络/peer/文件共享行为。
