## P0

### OQ-15-01 显示短 node_id 还是完整 node_id？

| 选项 | 说明 |
| --- | --- |
| A（当前） | 8 位短前缀 `alice (19b9b31e)` |
| B | 完整 36 字符 `alice (19b9b31e-...)` |
| C | 可配置 |

**当前 A**：

- 成员栏 26 列可读；
- 命令支持完整 node_id；
- 冲突时用完整 ID。

### OQ-15-02 前缀匹配规则

当前：

- 任意唯一前缀；
- 多个匹配 → 错误，要求完整 node_id。

可选：

- 最少 4 位；
- 只允许完整 8 位。

**当前**：任意唯一前缀，不限制最小长度；冲突报错。

### OQ-15-03 是否保留完整 IP/昵称寻址？

当前保留：

- 完整 node_id；
- node_id 前缀；
- 完整 IPv4；
- 昵称。

已移除：

- IPv4 最后一段（如 `103`）。

保留 IP/昵称是为了排障/兼容；node_id 是主标识。

### OQ-15-04 基础名已有 ` (8位hex)`？

当前：替换末尾的 ` (8位hex)` 为当前 node8，避免重复。

### OQ-15-05 历史保存什么？

当前：保存 `Message.name`（组合显示名）。旧历史不变。

## P1

### OQ-15-06 是否显示完整 node_id？

当前不显示。可选：成员栏第二行显示 `node 19b9…` 或帮助页说明如何查完整 ID。

### OQ-15-07 是否允许手工覆盖后缀？

不做。node_id 自动。

### OQ-15-08 同 node_id 多用户？

node_id 由 identity 文件生成；复制配置会导致冲突。网络仍按 node_id 去重，属于用户配置问题。

### OQ-15-09 文件提示的 `/recv file` 用短 ID 还是完整 ID？

当前短 ID；若前缀冲突，用户可手动输入完整 node_id。

### OQ-15-10 0.1.4 peer 看不到后缀

接受。0.1.4 没有新渲染逻辑；0.1.5 收到基础名后自行组合。

## 不做

- IP 最后一段；
- 反向 DNS；
- 用 IP 作为身份；
- 修改历史旧记录；
- 修改协议 name 字段；
- 自定义别名。
