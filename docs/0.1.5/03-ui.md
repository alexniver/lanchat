# 界面显示

> 状态：已实现
> 关联：[02-naming.md](02-naming.md) · [04-architecture.md](04-architecture.md)

## 1. 消息列表

```text
[alice@arch (19b9b31e)][2026-11-19 10:30:01]: 你好
[bob@arch (c81d46a5)][2026-11-19 10:30:05]: 在
```

- 名字由 `Message.name` 提供，发送/接收时已组合。
- 正文不变。
- `y` 复制正文。
- `Y` 复制完整行，包含 `(node8)`。
- 系统消息 `[系统]` 不受影响。
- 文件提示中的对方名使用 display name。

## 2. 成员侧边栏

```text
● alice@arch (node)
  (you) · 本机
● bob@arch (peer-1)
  192.168.1.103:47731
```

- 自己：`self_display_name()` + `(you)`。
- 他人：`PeerView.display_name`。
- 地址行仍显示 `IP:port`，方便排障。
- 不做私聊。

## 3. 文件提示

```text
[系统][...]: alice@arch (19b9b31e) 想发送文件 a.png（1.2 MB）。
             输入 /recv file 19b9b31e 接收。
```

- 提示中的 `/recv file` 使用短 node_id。
- `/send file a.png to 19b9b31e` 对应。
- 完整 node_id 也可用。
- 不再显示 `/recv file 101`。

## 4. 宽度

- 成员栏 26 列，`name (node8)` 通常可放；超长截断。
- 消息行/换行沿用 0.1.4。
- 不显示完整 36 字符 node_id 在消息/成员里；完整 ID 可从 `identity.json` 或 `/send` 目标获取。
- 帮助页不写死用户名。

## 5. 历史

- JSONL `name` 保存组合名。
- 旧记录无后缀，保持原样。
- 不新增字段。
- 复制完整行包含历史显示名。

## 6. 空名/短 ID

- 基础名空 -> `用户 (node8)`。
- node_id 空 -> 基础名。
- node_id 短于 8 -> 全文。
- 已有 ` (8位hex)` 后缀 -> 替换。
- 不做 IP 后缀，不显示 `(1)`/`(101)`。

## 7. 兼容

- 0.1.4 peer 发送基础名；0.1.5 根据 `Chat.from` 用 node_id 组合显示。
- 0.1.4 peer 看不到 0.1.5 的后缀（缺少新渲染），这是版本差异。
- 0.1.5 历史保存后缀；0.1.4 历史保持基础名。
