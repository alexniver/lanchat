# 0.1.1 范围与验收标准

> 状态：核心已实现，验收中
> 基线：0.1.0 已冻结
> 关联：[README.md](README.md) · [02-network.md](02-network.md) · [03-ui.md](03-ui.md)

## 1. 背景

0.1.0 已完成单机聊天内核：双 panel、Compose 输入栈、自动/手动选中、`y/Y` 复制、JSONL 历史、可配置键位、中文宽度和终端恢复。

0.1.1 的目标是把“本机消息”扩展为“局域网内其他节点也能收发”，同时**不破坏** 0.1.0 的交互。网络能力应该像 0.1.0 的本地发送一样自然：消息进入同一个列表、同一套历史、同一套自动/手动选中规则。

## 2. 目标

- 同一局域网内自动发现节点（mDNS），并支持手动地址兜底。
- 单房间 `#lobby` 文本群聊。
- 在线人数、连接状态可见；断线可重连。
- 远端消息与本地消息使用同一套显示/历史/选中逻辑。
- 不引入文件共享、私聊、历史同步等大范围功能。
- 0.1.0 的本地行为与测试全部保持通过。

## 3. 非目标（0.1.1 不做）

| 不做 | 说明 |
| --- | --- |
| 文件共享 / 文件传输 | 0.1.0 已删除，不恢复 |
| 多频道 / 私聊 | 单房间 `#lobby` |
| 历史同步 | 新节点只看到加入后的消息和本地历史 |
| 离线消息队列 / 应用层 ACK | 只保证在线节点收到；不保证离线补发 |
| 端到端加密 / 鉴权 | 明文局域网；文档明确风险 |
| 互联网中继 / NAT 穿透 | 仅可互通局域网 |
| 多行输入 | 0.1.1 保持单行 |
| 搜索 / 命令 / 帮助 | 0.1.0 P2 仍未做，0.1.1 不扩 |
| 文件/图片/语音/视频 | 不做 |
| 消息编辑/撤回/删除 | 不做 |
| 移动端 / Web UI | 不做 |

## 5. 功能需求

### FR-01 保持 0.1.0 本地行为

- `[必须]` 0.1.0 的单元/TUI 测试全部通过。
- `[必须]` 双 panel、Compose 栈、自动/手动选中、复制、历史、keymap 语义不变。
- `[必须]` 无网络时仍可完全本地使用；网络失败不阻塞 UI。
- `[必须]` `Q` 仍在 List 层退出；Compose 下仍只认 Enter/Esc 应用快捷键。

### FR-02 身份

- `[必须]` 复用 0.1.0 的 `identity.json` 的 `node_id`/昵称。
- `[必须]` 消息携带 node_id 与昵称；接收方校验 node_id 与握手一致。
- `[应该]` 昵称可在 0.1.1 修改（配置文件或后续命令）；不阻塞本版本。

### FR-03 发现

- `[必须]` mDNS 注册 `_lanchat._tcp.local.`；TXT 至少包含 `id`、`name`、`v`。
- `[必须]` 自动发现同服务节点；自身按 node_id 过滤，不按 IP+端口。
- `[必须]` 手动连接：`--connect host:port`（可重复）与配置 `seeds`。
- `[应该]` 成员离线后保留历史；重新出现时重新连接。

### FR-04 连接

- `[必须]` TCP 连接、版本握手、能力协商（0.1.1 只需 `chat`）。
- `[必须]` 连接/握手/读超时；不能无限“连接中”。
- `[必须]` 同一 node_id 只保留一条连接；重复连接有确定去重规则。
- `[必须]` 协议不兼容、身份重复时给出可读错误。
- `[应该]` 默认端口 47731；`--port` 可覆盖。

### FR-05 聊天

- `[必须]` 单房间 `#lobby` 广播；在线 peer 都收到。
- `[必须]` 消息包含 `msg_id`、`from`、`name`、`sent_at`、`body`、`room`。
- `[必须]` 单条消息 ≤ 16 KiB；帧 ≤ 64 KiB；超限拒绝并提示。
- `[必须]` 接收方按 `msg_id` 去重；本地发送也插入去重表。
- `[必须]` 发送不使用 `try_send` 静默丢弃；失败可见。
- `[应该]` 发送失败状态提示；不重发旧消息。
- `[不做]` 中继/转发；全 mesh 不完整时可能不互通（文档说明）。

### FR-06 选中与历史

- `[必须]` 远端消息进入同一个消息列表；格式不变；显示时间用本地接收时间。
- `[必须]` 自动模式：远端新消息自动选中最新并滚到底。
- `[必须]` 手动模式：远端新消息不改变选中/滚动；状态提示“有新消息”。
- `[必须]` 远端消息写入本地 JSONL 历史；重启后可回看。
- `[必须]` 历史记录增加可选 `from`（node_id）字段；旧记录缺省兼容。
- `[不做]` 历史同步。

### FR-07 在线状态与 UI

- `[必须]` 状态 panel 显示 `在线 N`（N 含本机）与连接状态。
- `[必须]` 连接中/在线/重连中/离线状态可见。
- `[必须]` 成员面板是右侧侧边栏（新 Layer），`Space u` 打开，再次 `Space u` 或 `Esc` 关闭。
- `[必须]` 成员面板显示昵称、`(you)`、地址、连接状态；`j/k` 选择；不做私聊。
- `[必须]` 成员面板不替换消息列表；Compose 下不响应 `Space u`。
- `[必须]` 节点加入/离开用状态/toast 提示，不插入消息列表（避免改变选中语义）。
- `[必须]` 连接/协议错误用状态/toast 提示。
- `[必须]` 0.1.1 不显示文件共享入口。

### FR-08 心跳与重连

- `[必须]` Ping/Pong；空闲超时断开。
- `[必须]` 断线指数退避重连（1s→30s，带抖动）。
- `[必须]` `Space r` 重连全部；`Space d` 手动断开（可选）；`--no-network` 回退本地。
- `[必须]` `Space d` 或配置可停止自动重连；0.1.1 不依赖命令模式。
- `[必须]` 重连成功后更新状态，不重复显示历史消息。

### FR-09 安全边界

- `[必须]` 明文传输；文档/README 明确“仅限可信局域网”。
- `[必须]` 不做加密/鉴权的声明写清楚。
- `[必须]` 不记录聊天正文到日志；历史权限 `0600`。
- `[必须]` 帧/消息大小上限，解析失败不崩溃。

## 6. 非功能需求

| ID | 需求 | 目标 |
| --- | --- | --- |
| NFR-01 | 发现延迟 | 同局域网 5s 内出现在线 |
| NFR-02 | 消息延迟 | LAN p95 < 100ms |
| NFR-03 | 重连 | 网络恢复后 30s 内恢复 |
| NFR-04 | 空闲 CPU | 网络空闲时 < 1% 单核 |
| NFR-05 | 内存 | 10k 消息 + 50 peers < 80MB |
| NFR-06 | 稳定性 | 24h 运行不崩溃、不泄漏 |
| NFR-07 | 回归 | 0.1.0 测试全部通过 |
| NFR-08 | 隐私 | 日志无正文；历史 `0600` |
| NFR-09 | 平台 | Linux 验收；macOS 尽量；Windows 记录限制 |
| NFR-10 | 协议 | 版本化；不兼容有提示 |
| NFR-11 | 安全 | 大小上限、去重、超时、重复连接处理 |

## 7. 验收标准

### 7.1 本地回归

- [ ] 0.1.0 的 57 个测试全部通过。
- [ ] 无网络时启动、输入、发送、历史、复制、`Q` 退出正常。
- [ ] Compose 下 `j/k/y/Y/i/Q` 仍作为文字输入。

### 7.2 发现与连接

- [ ] 两台同局域网机器 5s 内互相发现，状态显示在线。
- [ ] `--connect host:port` 可连接未通过 mDNS 发现的对端。
- [ ] 协议版本不兼容/重复 node_id 有可读提示，不崩溃。
- [ ] 同一 node_id 重复连接只保留一条，不出现双份消息。

### 7.3 聊天与选中

- [ ] A 发送消息，B 列表按 `[name][datetime]: message` 显示。
- [ ] 自动模式下 B 自动选中最新；手动模式下 B 选中不变。
- [ ] 同一消息重复投递只显示一次。
- [ ] 消息/帧超限被拒绝并提示。
- [ ] 发送失败可见，不静默丢。

### 7.4 重连与状态

- [ ] 断开网络后状态变为重连中；恢复后 30s 内自动重连。
- [ ] 在线人数随 peer 上下线更新。
- [ ] 节点加入/离开提示不改变消息选中（若采用状态提示）。
- [ ] `Space u` 打开/关闭右侧成员侧边栏；`j/k` 选择，`Esc` 关闭。
- [ ] 成员面板不影响消息列表、自动/手动选中和 Compose。

### 7.5 安全与历史

- [ ] 日志中无消息正文。
- [ ] 历史文件权限 `0600`；远端消息重启后可回看。
- [ ] 历史旧格式（无 `from`）兼容。
- [ ] `cargo fmt/clippy/test/build` 通过；无文件共享依赖。

## 8. 假设与依赖

- 节点在同一广播域，mDNS 多播可用；不可用时手动连接。
- 节点间 TCP 可直连；无 NAT/防火墙穿透。
- 明文局域网被视为可信环境；0.1.1 不做加密。
- 0.1.0 的本地 UI/历史/键位是稳定基线。
- 全 mesh 不完整时允许部分节点不互通，文档说明。
