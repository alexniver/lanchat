# 0.1.2 范围与验收标准

> 状态：核心已实现，验收中
> 目标：点对点文件传递（不是目录同步）
> 关联：[README.md](README.md) · [02-commands.md](02-commands.md) · [03-transfer.md](03-transfer.md)

## 1. 背景

0.1.1 已经能通过 mDNS + TCP 在局域网聊天。用户经常需要把本地文件发给同一局域网的另一位在线用户，但不想搭建共享目录、FTP 或网盘。

0.1.2 提供一种“聊天里顺手发文件”的方式：

- 用 `/send file` 指定文件和对方；
- 对方用 `/recv file` 明确同意后才开始传输；
- 超时自动取消，避免请求一直挂着；
- 文件落到固定目录，重名不覆盖。

**不是同步**：不扫描目录、不自动上传、不保持两端一致。

## 2. 目标

- `/` 开头进入命令输入；未知 `/...` 按普通聊天消息发送。
- 明确的点对点文件请求/接收流程。
- 10 分钟请求超时；超时双方可见。
- 同一文件重复请求拦截。
- 一次 `/recv` 接收指定对方所有待接收文件。
- 接收文件保存到 XDG 数据目录下的 `lanchat/files`，重名自动编号。
- 全程有通俗、可操作的提示。
- 不破坏 0.1.1 的聊天/键位/历史/选中行为。

## 3. 非目标（0.1.2 不做）

| 不做 | 说明 |
| --- | --- |
| 目录同步 / 自动同步 | 只做用户明确发起的文件传递 |
| 自动接收 | 必须 `/recv file <对方>` |
| 断点续传 | 中断后重传，不续传 |
| 多文件打包成 zip | 每个文件一个请求，逐个传输 |
| 文件夹递归发送 | 只发普通文件 |
| 互联网/NAT 穿透 | 仅同一局域网 |
| 加密 / 鉴权 | 明文；仅可信局域网 |
| 接收后自动打开/执行 | 只保存，不执行 |
| 断线重连后恢复未完成传输 | 0.1.2 不恢复 |
| 文件历史浏览 UI | 文件保存到目录；不做专门文件管理器 |
| 传输限速/队列管理 | 可先顺序传输；不做复杂调度 |

## 5. 功能需求

### FR-01 `/` 输入与命令解析

- `[必须]` 在 List 层按 `/`：打开 Compose，输入框预填 `/`，选中高亮隐藏。
- `[必须]` Compose 下继续输入完整命令；Enter 提交。
- `[必须]` 提交内容以 `/` 开头时：
  - 是已注册命令且参数合法 → 执行命令，不发送聊天消息；
  - 是已注册命令但格式错误 → 显示用法提示，不发送聊天消息；
  - 不是已注册命令 → 按普通聊天消息发送（保留开头的 `/`）。
- `[必须]` 不以 `/` 开头时，仍按 0.1.1 普通消息发送。
- `[应该]` `/help` 或 `/commands` 列出命令（可后置）。
- `[应该]` 命令名大小写策略明确（建议小写）。

### FR-02 发送文件请求

- `[必须]` 语法：`/send file <本地文件路径> to <对方>`。
- `[必须]` `<本地文件路径>` 支持 `~`/相对/绝对路径；必须是可读普通文件。
- `[必须]` `<对方>` 支持完整 IP、IP 最后一段（`101`/`103`）、在线昵称（至少一种，建议都支持）。
- `[必须]` 只发给当前在线 peer；找不到对方时给可读提示。
- `[必须]` 发送方收到“请求已发出，等待对方接收”的提示。
- `[必须]` 接收方收到可操作提示，包含文件名、大小、发送方、`/recv file <发送方>`。
- `[必须]` 请求未接收超过 10 分钟 → 自动取消，双方提示。
- `[必须]` 同一对方 + 同一文件名仍有未完成请求时，拒绝重复发送并提示。
- `[应该]` 同一对方多个文件 → 每个文件独立请求；也可由一次 `/send` 只发一个。
- `[应该]` 文件大小、文件名长度有上限；超限提示。
- `[必须]` 源文件路径不存在/不可读/是目录 → 提示，不创建请求。

### FR-03 接收文件

- `[必须]` 语法：`/recv file <对方>`。
- `[必须]` 接收该对方**全部**待接收文件。
- `[必须]` 没有待接收文件时给可读提示。
- `[必须]` 接受后显示“开始接收文件”。
- `[必须]` 文件保存到 `~/.local/share/lanchat/files`（XDG 数据目录下的 `lanchat/files`）。
- `[必须]` 重名时使用 `<stem>[n].<ext>`，n 从 0 开始递增，直到找到未占用名称。
- `[必须]` 写入使用临时文件 + rename，避免留下半个文件。
- `[必须]` 接收完成显示：来源、文件名、最终保存路径；若改过名要说明。
- `[必须]` 接收失败显示失败原因；清理临时文件。
- `[应该]` `/recv` 不带参数时列出待接收文件或给用法提示（OQ-12-08）。
- `[应该]` 多文件接收时逐个显示进度/结果。
- `[不做]` 自动接收、断点续传、接收后自动打开。

### FR-04 请求生命周期

- `[必须]` 状态：`Pending`（等待接收）→ `Accepted/Transferring` → `Completed` / `Cancelled` / `TimedOut` / `Failed`。
- `[必须]` Pending 超时 10 分钟；Accepted 后不再按请求超时取消。
- `[必须]` 超时向双方发消息：请求已取消，原因“对方 10 分钟未接收”。
- `[必须]` 发送方主动断开/退出时，待接收请求取消并通知接收方（若连接还在）。
- `[应该]` 接收方断开时，发送方收到失败/取消提示。
- `[应该]` 传输中超过一段空闲时间无进度时失败（OQ-12-07）。
- `[不做]` 请求持久化到磁盘；进程退出后未完成请求丢失（D-013）。

### FR-05 提示与系统消息

- `[必须]` 文件请求/开始/成功/取消/失败使用**系统消息**显示在消息列表（建议）。
- `[必须]` 系统消息格式与用户消息可区分，例如 `[系统][HH:MM:SS]: ...`。
- `[必须]` 系统消息中的 `/recv file 101` 可直接复制。
- `[应该]` 命令错误/即时反馈用状态栏/toast，不污染聊天列表。
- `[应该]` 传输进度显示在状态栏或系统消息。
- `[必须]` 所有提示语通俗、可操作，不暴露内部错误码。

### FR-06 多文件

- `[必须]` 同一发送方待接收多个文件时，`/recv file 101` 全部接受。
- `[必须]` 逐文件传输、逐文件成功/失败；一个失败不阻塞其他文件（建议）。
- `[应该]` 接收请求提示可汇总：`101 想发送 2 个文件：a.png、b.jpg`。
- `[必须]` 重名处理对每个文件独立执行。

### FR-07 安全/限制

- `[必须]` 只接受普通文件；拒绝目录、设备文件等。
- `[必须]` 发送端路径必须存在且可读；接收端文件名只取 basename，拒绝 `../` 和路径分隔符。
- `[必须]` 单文件上限 1 GiB；每发送方 20 个待接收；全局 100 个；数据块 16 KiB。
- `[必须]` 不自动执行接收文件；不覆盖已有文件。
- `[必须]` 明文传输；与 0.1.1 相同的可信局域网边界。
- `[应该]` 发送/接收分块，文件内容走独立数据连接，避免阻塞聊天（D-011）。
- `[必须]` 传输失败/超时清理 `.part` 临时文件。

## 7. 验收标准

### 7.1 命令输入

- [ ] List 按 `/` 打开 Compose，输入框已有 `/`。
- [ ] `/not-a-command` 作为普通消息发送并显示。
- [ ] `/send file` 参数缺失时显示用法，不发送消息。
- [ ] `/recv file` 参数缺失时显示用法。

### 7.2 发送/接收

- [ ] A 输入 `/send file ~/Download/a.png to 103`，B 收到文件请求提示。
- [ ] B 输入 `/recv file 101`，开始接收，文件保存到 files 目录。
- [ ] A 显示发送成功；B 显示接收成功及路径。
- [ ] 重名时保存为 `a[0].png` / `a[1].png`。
- [ ] B 一次接收 A 的多个待接收文件，全部保存。
- [ ] 请求提示包含 `/recv file 101`，可直接复制。

### 7.3 超时/重复/错误

- [ ] 10 分钟不接收，双方看到请求取消提示。
- [ ] 同一 A→B 的 a.png 未完成时再次 `/send` 被拦截并提示。
- [ ] 源文件不存在/不可读/是目录时提示，不创建请求。
- [ ] 对方离线/找不到时提示，不创建请求。
- [ ] 接收写入失败时显示失败，清理临时文件。

### 7.4 安全/回归

- [ ] 接收端不会写到 files 目录之外。
- [ ] 不覆盖已有文件；不自动执行。
- [ ] 传输中聊天仍可用。
- [ ] 0.1.1 的 73 个测试继续通过（当前总计 90）；0.1.1 聊天/成员/重连无回归。

## 8. 假设

- 双方已经通过 0.1.1 的网络连接在线。
- 控制消息走现有 peer 连接；文件内容走独立 TCP 数据连接（D-011）。
- 明文局域网被视为可信；0.1.2 不做加密/鉴权。
- 文件系统消息不写入历史；Pending 请求只在当前运行有效。
- 大文件允许传输，但不是“秒传”；0.1.2 不做断点续传。
- 请求只保存在内存，进程退出后未完成请求失效。
