# lanchat 0.1.2 文件传递需求讨论

> 状态：**0.1.2 核心已实现，验收中**（0.1.1 已冻结）
> 版本：0.1.2
> 建立日期：2026-11-19

## 一句话目标

在 0.1.1 的局域网聊天基础上，加入**点对点文件传递**：

- 用 `/` 开头输入命令；
- `/send file <本地路径> to <对方>` 发起传递；
- `/recv file <对方>` 接收对方待传的文件；
- 10 分钟未接收自动取消；
- 同一文件重复请求会被拦截；
- 接收文件自动保存到 `~/.local/share/lanchat/files`，重名自动加 `[0]`、`[1]`。

> **注意**：这不是“同步文件夹”，不会自动扫描、自动上传或保持两端目录一致。必须由用户明确发送和接收。

## 典型场景

1. `192.168.1.101` 输入：

```text
/send file ~/Download/a.png to 103
```

2. `192.168.1.103` 的消息列表显示：

```text
192.168.1.101 想发送文件 a.png（1.2 MB）。输入 /recv file 101 接收。
```

3. `192.168.1.103` 输入：

```text
/recv file 101
```

4. 103 显示“开始接收文件”，文件保存到：

```text
~/.local/share/lanchat/files/a.png
```

5. 接收完成后：

- 103：`接收完成：来自 192.168.1.101 的 a.png 已保存到 ~/.local/share/lanchat/files/a.png。`
- 101：`发送完成：a.png 已发送给 192.168.1.103。`

如果 103 在 10 分钟内没有输入 `/recv file 101`，双方会看到请求取消提示。

## 范围速览

| 能力 | 0.1.2 | 说明 |
| --- | --- | --- |
| `/` 输入命令 | ✅ 做 | `/` 打开输入 panel 并预填 `/` |
| 未知 `/...` 当普通消息 | ✅ 做 | 不是合法命令就按普通消息发送 |
| `/send file ... to ...` | ✅ 做 | 点对点发送文件请求 |
| `/recv file ...` | ✅ 做 | 接收指定对方的全部待接收文件 |
| 10 分钟请求超时 | ✅ 做 | 未接收自动取消并通知双方 |
| 重复请求保护 | ✅ 做 | 同一对方 + 同一文件名，未完成时拦截 |
| 多文件接收 | ✅ 做 | 一次 `/recv` 接收该对方全部待接收文件 |
| 自动保存 + 重名处理 | ✅ 做 | 保存到 files 目录；重名加 `[0]`/`[1]` |
| 文件系统消息 | ✅ 做 | 请求/开始/成功/取消显示在消息列表，不写历史 |
| 传输进度 | 🟡 待定 | 可先只显示开始/完成 |
| 取消命令 | 🟡 待定 | 超时自动取消；手动取消可选 |
| 断点续传 | ❌ 不做 | 0.1.2 不恢复中断的传输 |
| 文件夹同步 | ❌ 不做 | 不是同步工具 |
| 自动接收 | ❌ 不做 | 必须明确 `/recv` |
| 加密 / 鉴权 | ❌ 不做 | 沿用 0.1.1 明文边界 |
| 互联网传输 | ❌ 不做 | 仅局域网 |

## 与 0.1.1 的关系

- 0.1.1 的聊天、成员侧边栏、在线状态、自动/手动选中、历史、键位保持不变。
- 控制消息复用现有 peer/TCP 连接；文件内容走独立数据 TCP 连接；复用 node_id 身份。
- 不恢复 0.1.0 时期的“共享目录自动列表/下载”模型。
- 0.1.1 的安全边界（明文、无鉴权）继续适用。

## 术语

| 术语 | 含义 |
| --- | --- |
| 文件请求 / offer | 发送方发起、等待接收方确认的一次文件传递 |
| 接收 / accept | 接收方输入 `/recv file <对方>`，同意接收 |
| 传输 / transfer | 接收方同意后，实际传输文件内容 |
| 对方标识 | 完整 IP、IP 最后一段（如 `101`）、或在线昵称 |
| 系统消息 | 文件请求/开始/成功/取消等提示，不是用户聊天 |
| files 目录 | `~/.local/share/lanchat/files`（由 XDG 数据目录决定） |
