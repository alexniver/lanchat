# 命令与提示语

> 状态：已实现
> 关联：[01-scope.md](01-scope.md) · [03-transfer.md](03-transfer.md) · [04-ui.md](04-ui.md)

## 1. `/` 输入

- 在消息列表（List 层）按 `/`：
  - 打开 Compose 输入 panel；
  - 输入框预填 `/`；
  - 消息列表选中高亮隐藏，和 0.1.1 打开输入 panel 的行为一致。
- 继续输入完整命令，Enter 提交。
- `i` 仍打开空输入框（普通消息）。
- Compose 下 `/` 只是普通字符；不会再次“打开命令模式”。

## 2. 提交规则

对 Enter 提交的内容：

```text
以 / 开头？
├─ 否 → 按普通聊天消息发送
└─ 是 → 查命令表
    ├─ 找到且参数合法 → 执行命令，不发送聊天消息
    ├─ 找到但参数不合法 → 显示用法提示，不发送聊天消息
    └─ 没找到 → 按普通聊天消息发送（保留开头的 /）
```

关键点：

- **未知命令当普通消息**，例如 `/hello` 会作为聊天内容发送。
- **已识别命令但写错参数**，不当普通消息，避免把半截命令发给别人。
- 命令名区分大小写；推荐全小写。
- 空命令 `/` 按未知内容处理（作为普通消息发送），除非后续决定改为帮助入口。

## 3. 命令表

### 3.1 `/send file`

```text
/send file <本地文件路径> to <对方>
```

示例：

```text
/send file ~/Download/a.png to 103
/send file "./my photo.png" to 192.168.1.103
```

- `<本地文件路径>`：
  - 支持 `~` 展开、相对路径、绝对路径。
  - 必须是存在、可读的普通文件；目录/设备文件拒绝。
  - 路径可以带空格：推荐用引号包住；也可以把 `file` 和最后一个 ` to ` 之间的内容整体当作路径。
- `<对方>`：
  - 完整 IP，如 `192.168.1.103`；
  - IP 最后一段，如 `103`（在当前在线节点中匹配）；
  - 在线昵称（建议支持）；
  - 找不到或匹配到多个时提示。
- 一次命令只发一个文件。多个文件分多次 `/send`。

### 3.2 `/recv file`

```text
/recv file <对方>
```

示例：

```text
/recv file 101
/recv file 192.168.1.101
```

- 接收该对方**全部**待接收文件。
- 没有待接收文件时提示。
- 建议 `/recv file` 不带参数时列出待接收请求和用法（OQ-12-08）。

## 4. 对方标识解析

按以下顺序解析 `<对方>`：

1. 完整 IP 完全匹配在线 peer 的监听地址；
2. 纯数字（如 `101`）匹配在线 peer IPv4 的最后一段；
3. 昵称完全匹配（建议大小写不敏感）；
4. 都不匹配 → “找不到在线用户”；
5. 匹配到多个 → “匹配到多个用户，请用完整 IP”。

显示给用户时优先使用简短形式：

- 对方 IP 最后一段，例如 `101`；
- 消息里可以同时带完整 IP，避免歧义。

## 5. 提示语（通俗版）

> 下面是我建议的用户可见文案。比原始需求更短、更明确，并告诉用户下一步该做什么。

### 5.1 发送方

| 场景 | 提示 |
| --- | --- |
| 请求已发出 | `已向 192.168.1.103 发送 a.png 的接收请求，等待对方接收（10 分钟内有效）。` |
| 多个请求已发出 | `已向 192.168.1.103 发送 2 个文件的接收请求，等待对方接收（10 分钟内有效）。` |
| 对方接收、开始传输 | `对方已接收 a.png，开始发送…` |
| 发送成功 | `发送完成：a.png 已发送给 192.168.1.103。` |
| 发送超时取消 | `a.png 的发送请求已取消：对方 10 分钟内没有接收。` |
| 对方取消 | `192.168.1.103 取消了 a.png 的接收。` |
| 重复请求 | `a.png 的请求已经发给 192.168.1.103 了，请等对方接收完成后再发。` |
| 找不到对方 | `找不到在线用户 103。请确认对方在线，或使用完整 IP。` |
| 匹配到多个 | `103 匹配到多个在线用户，请改用完整 IP，例如 192.168.1.103。` |
| 路径不存在 | `找不到文件 ~/Download/a.png，请检查路径。` |
| 路径不可读 | `无法读取 a.png，请检查文件权限。` |
| 不是普通文件 | `a.png 不是普通文件；0.1.2 只支持发送单个文件。` |
| 文件过大 | `a.png 太大（上限 1 GiB），请换一个文件。` |
| 对端传输失败 | `发送失败：a.png 没有传完，请重试。` |

### 5.2 接收方

| 场景 | 提示 |
| --- | --- |
| 收到单个请求 | `192.168.1.101 想发送文件 a.png（1.2 MB）。输入 /recv file 101 接收。` |
| 收到多个请求 | `192.168.1.101 想发送 2 个文件：a.png（1.2 MB）、b.jpg（340 KB）。输入 /recv file 101 全部接收。` |
| 开始接收 | `开始接收来自 192.168.1.101 的文件：a.png…` |
| 接收成功 | `接收完成：来自 192.168.1.101 的 a.png 已保存到 ~/.local/share/lanchat/files/a.png。` |
| 重名改名 | `接收完成：a.png 已存在，已另存为 a[0].png。` |
| 多文件完成 | `接收完成：来自 192.168.1.101 的 2 个文件已全部保存。` |
| 请求超时 | `a.png 的接收请求已取消：超过 10 分钟没有接收。` |
| 对方取消 | `192.168.1.101 取消了 a.png 的发送。` |
| 没有待接收 | `没有来自 192.168.1.101 的待接收文件。` |
| 接收失败 | `接收失败：a.png 没有保存成功；已清理临时文件。` |
| 磁盘空间不足 | `接收失败：磁盘空间不足，a.png 没有保存。` |

### 5.3 命令错误（状态栏/toast，不进入聊天列表）

| 场景 | 提示 |
| --- | --- |
| `/send` 参数缺失 | `用法：/send file <文件路径> to <对方>` |
| `/recv` 参数缺失 | `用法：/recv file <对方>` |
| 不认识的命令 | 不提示；把整条内容作为普通消息发送 |
| 未登录/网络关闭 | `当前是本地模式，不能发送文件。` |

## 6. 消息显示

- 文件请求、开始、成功、取消、失败显示为**系统消息**：

```text
[系统][2026-11-19 10:31:12]: 192.168.1.101 想发送文件 a.png（1.2 MB）。输入 /recv file 101 接收。
```

- 系统消息用灰色/不同前缀，和用户消息区分。
- 命令语法错误、找不到用户、重复请求等即时反馈放状态栏/toast，不插入列表。
- 系统消息不写入本地历史，只保存在当前运行内存，避免重启后出现已失效请求。
