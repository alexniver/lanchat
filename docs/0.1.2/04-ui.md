## 1. `/` 输入体验

在消息列表按 `/`：

```text
┌ 输入 ──────────────────────────────────────────────┐
│ /▌                                                 │
└────────────────────────────────────────────────────┘
```

- 输入框立即出现，光标在 `/` 后面。
- 继续输入，例如 `/send file ~/Download/a.png to 103`。
- Enter 提交；Esc 取消。
- 输入框里已经有一个 `/`，用户不需要再按一次。
- `i` 仍然打开空输入框，用于普通消息。

命令解析结果：

| 输入 | 行为 |
| --- | --- |
| `/send file ... to ...` 合法 | 执行发送请求 |
| `/recv file ...` 合法 | 开始接收 |
| `/send file` 参数缺失 | 状态提示用法，不发送消息 |
| `/hello` 未注册 | 作为普通消息发送 `/hello` |
| `hello` | 普通消息 |

## 2. 文件消息放哪里

已确认：**文件请求/开始/成功/取消用系统消息，显示在消息列表**。

原因：

- 请求需要持续可见，不能只闪 2 秒 toast；
- 用户需要看到 `/recv file 101` 并复制；
- 多次请求/多文件需要留在列表里回看。

显示示例：

```text
[系统][10:30:05]: 192.168.1.101 想发送文件 a.png（1.2 MB）。输入 /recv file 101 接收。
[系统][10:30:20]: 开始接收来自 192.168.1.101 的文件：a.png…
[系统][10:30:23]: 接收完成：来自 192.168.1.101 的 a.png 已保存到
                  ~/.local/share/lanchat/files/a.png。
```

- 系统消息用灰色/不同前缀，和 `[name][datetime]: message` 区分。
- 系统消息可被选中、复制；`y` 复制正文，`Y` 复制完整行。
- 自动/手动选中规则与普通新消息一致：
  - 自动模式：新系统消息选中最新；
  - 手动模式：不打断浏览，状态提示“有新消息”。
- 系统消息不写入历史，避免重启后出现已失效请求。

## 3. 命令错误

以下即时反馈放状态栏/toast，不进入消息列表：

- 命令格式错误；
- 找不到用户；
- 重复请求；
- 源文件不存在/不可读/太大；
- 没有待接收文件；
- 当前 `--no-network` 本地模式。

示例状态：

```text
在线 2 · 消息 12 · 选中 12/12 · 自动 · ● online · 找不到在线用户 103
```

## 4. 文件请求提示

### 4.1 接收方

单文件：

```text
[系统][10:30:05]: 192.168.1.101 想发送文件 a.png（1.2 MB）。输入 /recv file 101 接收。
```

多文件：

```text
[系统][10:30:05]: 192.168.1.101 想发送 2 个文件：a.png（1.2 MB）、b.jpg（340 KB）。
                  输入 /recv file 101 全部接收。
```

- 提示里带发送方短标识（`101`）和 `/recv` 命令，用户可直接照抄。
- 完整 IP 可在成员侧边栏查看；提示不必写太长。
- 如果发送方 IP 不是 192.168.1.x，仍用最后一段；完整 IP 作为兜底。

### 4.2 发送方

```text
[系统][10:30:05]: 已向 192.168.1.103 发送 a.png 的接收请求，等待对方接收（10 分钟内有效）。
```

- 发送请求后不自动传输；必须等对方 `/recv`。
- 10 分钟倒计时不必逐秒显示；超时提示即可。

## 5. 接收进度

0.1.2 建议先做“开始/完成”，进度作为可选：

### 5.1 最简版

```text
[系统][10:30:20]: 开始接收来自 192.168.1.101 的文件：a.png…
[系统][10:30:23]: 接收完成：… a.png 已保存到 …
```

### 5.2 进度版（可选）

状态栏：

```text
在线 2 · 消息 12 · 选中 12/12 · 自动 · ● online · 接收 a.png 45%
```

或多文件：

```text
正在接收 2/3：b.jpg 70%
```

- 进度更新不能每块都重绘过频；建议 100–250 ms 节流。
- 大文件传输时状态栏始终可见，聊天仍可用。

## 6. 多文件

- 接收方收到汇总请求；
- `/recv file 101` 一次性接受该发送方全部 Pending 文件；
- 逐文件显示开始/完成；
- 每个文件独立命名（a[0].png、b.jpg…）；
- 最后显示汇总：

```text
接收完成：来自 192.168.1.101 的 2 个文件已全部保存。
```

- 如果其中一个失败：

```text
接收完成：a.png 成功；b.jpg 失败（磁盘空间不足）。
```

## 7. 超时/取消/失败

### 7.1 超时

双方：

```text
[系统][10:40:05]: a.png 的接收请求已取消：超过 10 分钟没有接收。
```

接收方也可以更短：

```text
a.png 的请求已取消：10 分钟内没有输入 /recv file 101。
```

### 7.2 对方断开

```text
[系统][10:35:12]: 192.168.1.101 已断开，未完成的文件请求已取消。
```

### 7.3 传输失败

```text
[系统][10:35:12]: 接收失败：a.png 没有保存成功；已清理临时文件。
```

- 不显示内部错误码/堆栈；详细错误只写日志。
- 接收失败时不要留下半文件。

## 8. 重名提示

```text
[系统][10:30:23]: 接收完成：a.png 已存在，已另存为 a[0].png。
```

- 提示最终路径，用户不用猜。
- 多个重名：`a[0].png`、`a[1].png`。

## 9. 状态栏

文件传输期间，状态栏可增加一段：

```text
● online · 接收 a.png 45%
```

或空闲时保持原样：

```text
在线 2 · 消息 12 · 选中 12/12 · 自动 · ● online
```

- 文件请求/成功/超时用系统消息；状态栏只放临时进度/错误。
- 不遮挡 Compose 输入提示；Compose 下仍显示 `输入中 · Enter 发送 · Esc 取消`。

## 10. 成员侧边栏

文件传递复用 0.1.1 的成员侧边栏：

- `Space u` 打开/关闭；
- 显示 `(you)`、昵称、地址、连接状态；
- 不做私聊；
- 文件传递不改变成员面板行为。

## 11. 提示语原则

1. 先说要做什么，再给命令。
2. 不写“协议错误/帧错误”等内部词。
3. 成功提示带来源、文件名、最终路径。
4. 重名时明确说“已另存为”。
5. 超时说明“10 分钟”和“没有接收”。
6. 重复请求说明“已经发过”和“等接收完成后再发”。
7. 不显示完整堆栈/错误码。
