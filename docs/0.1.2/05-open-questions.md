## 已确认（来自需求）

| 项目 | 结论 |
| --- | --- |
| 功能定位 | 文件传递，不是目录同步 |
| `/` 输入 | 打开输入 panel 并预填 `/` |
| 未知 `/...` | 当普通消息发送 |
| 发送命令 | `/send file <path> to <对方>` |
| 接收命令 | `/recv file <对方>` |
| 请求超时 | 10 分钟；超时双方提示 |
| 重复请求 | 同一文件未完成时拦截 |
| 多文件 | `/recv` 接收该对方全部待接收文件 |
| 保存目录 | `~/.local/share/lanchat/files`（XDG 数据目录） |
| 重名 | 文件名后加 `[0]`、`[1]` 自增 |
| 接收方式 | 必须手动 `/recv`，不自动接收 |

| 选项 | 说明 |

### OQ-12-03 带空格的路径怎么解析？

| 选项 | 说明 |
| --- | --- |
| A（推荐） | 路径可加引号；否则取 `file ` 与最后一个 ` to ` 之间的全部内容 |
| B | 路径不能有空格 |
| C | 只支持引号 |

**推荐 A**：兼容 `~/Download/a.png` 和 `"./my photo.png"`；` to ` 作为分隔符，路径中出现 ` to ` 时建议加引号。

### OQ-12-04 重复请求的去重 key？

| 选项 | 说明 |
| --- | --- |
| A（推荐） | `(接收方 node_id, 文件 basename)`，Pending/Transferring 时拦截 |
| B | 完整本地路径 + 接收方 |
| C | 文件内容 hash + 接收方 |

**推荐 A**：符合“同一用户再次发 a.png”描述；完成后允许重发。不同路径但同名也算重复。

---

### OQ-12-05 文件大小/数量上限？

**已确认 A**（D-012）：

- 单文件 1 GiB；
- 每个发送方最多 20 个待接收文件；
- 全局最多 100 个待接收；
- 数据块原始 16 KiB；
- 文件名 ≤ 255 字节。

超限在 `/send` 或 FileOffer 阶段拒绝并提示。

---

### OQ-12-06 文件内容走哪条通道？

| 选项 | 说明 |
| --- | --- |
| A | 复用现有 peer TCP 连接，分块 base64 传输 |
| B（已确认） | 独立数据 TCP 连接 |
| C | 走 HTTP/其他协议 |

**已确认 B**（D-011）：控制消息走现有 peer 连接，文件内容走独立 TCP 数据连接，避免阻塞聊天。数据连接复用监听端口，首帧区分用途。

---

### OQ-12-07 接受后传输阶段的超时？

| 选项 | 说明 |
| --- | --- |
| A（推荐） | 连续 60 秒没有进度 → 失败；不设总时长 |
| B | 总时长 10 分钟 |
| C | 不设超时，靠用户取消 |

**推荐 A**：避免大文件被总时长误杀；卡死 60 秒可见。10 分钟只用于“等待接收”。

---

### OQ-12-08 `/recv file` 不带参数？

| 选项 | 说明 |
| --- | --- |
| A（推荐） | 列出待接收文件及用法，不自动接收 |
| B | 接收所有发送方的所有文件 |
| C | 直接报用法错误 |

**推荐 A**：安全、可发现；用户仍需指定发送方。

---

### OQ-12-10 系统消息是否写入历史？

| 选项 | 说明 |
| --- | --- |
| A（推荐） | 不写入；只在当前运行显示 |
| B | 写入；重启后还能看到 |

**已确认 A**（D-013）：系统消息不写历史；文件本身仍在 files 目录。

## P1：体验细节

### OQ-12-09 是否提供手动取消？

**推荐**：`/cancel file <对方>` 可选（P1）。0.1.2 至少有 10 分钟超时和断线取消；手动取消方便但可后置。

### OQ-12-11 是否做 SHA256 校验？

**推荐**：0.1.2 不做。TCP 保证传输完整性；文件大小可校验；SHA256 增加读盘/CPU，后续需要时再加。

### OQ-12-12 重名格式

**已确认 A**（D-015）：`a[0].png` / `a[1].png`；无扩展名 `report[0]`。

### OQ-12-13 是否做传输进度？

**推荐**：0.1.2 先做“开始/完成”，进度作为 P1（状态栏百分比）；大文件体验更好但会增加 UI/节流逻辑。

### OQ-12-14 多文件传输顺序

**推荐**：按请求创建顺序；逐文件完成/失败；一个失败不阻塞其他（可配置）。

### OQ-12-15 源文件是符号链接？

**推荐**：跟随符号链接读取目标文件；但必须是普通文件。若目标不可读/循环/消失 → 报错。

### OQ-12-16 发送给自己？

**推荐**：拒绝，提示“不能发给自己”。

### OQ-12-17 对端不支持文件传递？

**推荐**：Hello capability 不含 `file_transfer` → 提示“对方版本不支持文件传递，请升级后重试”，不发送文件帧（避免旧客户端断开）。

### OQ-12-18 命令名大小写/未知命令

**推荐**：命令小写；`/SEND` 视为未知命令按普通消息发送。若后续希望大小写不敏感，再调整。
